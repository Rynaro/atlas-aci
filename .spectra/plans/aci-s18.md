## Approach

### Reuse one authenticated generation and real bounded producers

S17 retrieve(reader,...) consumes an acquired native9 reader; S12 navigate(reader,...)
can use that SAME connection. Both install/clear their own SQLite progress hooks.
Compose them sequentially; never recursively call public dispatch, reopen the factory,
or combine results from independently acquired generations. S13 registry.install can
retain prebuilt canonical pages and the actual owner context, but does not validate their
semantic schema: S18 must validate every new page before atomic installation.

Select one owned-reader context builder with bounded collection and whole-bundle
admission. Default continuation=false uses a normal request lease, immutable source
references and one response. continuation=true reserves a S13 pending slot, acquires
ONE reader with its optional authenticated chunk catalog, builds all pages/resources,
then transfers ownership only after validation/capacity checks. No source URI is issued
without that retained owner. Existing status/retrieve/navigation/page/continue outputs
and semantics remain unchanged; the seven tool names remain.

First checkpoint: freeze and hash useful-span fixtures/labels and lexical baseline
BEFORE implementing the packer/ranker. Then demonstrate one real G1 retrieve→expand→
complete-bundle path, actual byte accounting and an exact configured tokenizer on both
SDK representations. With continuation, publish G2/G3/prune while G1 page/resource
still reads the original proof bytes. Stop if composition needs a new durable service
or silently resets work budgets; no latest-reader fallback.

### Input, shared work and canonical collection

Add closed atlas.graph.v1 op=context with task text, optional expected_generation_id,
repository/path filters inherited from S17, relation/direction/confidence constraints
inherited from S12, optional target selector for path expansion, max_bytes, finite
collection/work/depth/seed/bundle limits and continuation boolean. Default limits:
32 retrieval candidates,8 entity expansion seeds,128 collected bundles,8MiB canonical
collection,256 total examined edges,depth2,1000000 aggregate SQL VM operations and
2000ms post-acquisition context deadline. Validate finite integer types/ranges and
server upper bounds; bool is not an integer allowance. No unbounded user override.

Request max_bytes remains the hard emitted-result byte cap. This slice does not add
a max_tokens constraint: optional token usage is reported exactly for a declared
algorithm or explicitly estimated, never promoted to a model-independent hard limit.
Source inline policy defaults to inline_if_complete with8192 total raw inline bytes;
references is also supported. No arbitrary substring/snippet search engine is added.

One request budget object owns the absolute post-authentication deadline and remaining
SQL/edge/hydration allowances. Give each retrieval/navigation call only its remaining
allowance; subtract actual charged work before another call. Source authentication
and existing full-generation validation are separately observed, outside that traversal
clock/counter claim. Sequential progress hooks must clear in finally; do not stack them
or let each seed renew a full deadline/edge allowance. Additional proof PK hydration,
source reads, ranking and token accounting have finite counts/setup checks as well.

Run one bounded retrieval collection under its OWN collection allowance, not the small
first-response byte cap. Preserve exact-first candidate order and coverage diagnostics.
Expand selected entity IDs only; a lexical file candidate is not a guessed entity or
call target. Use neighborhood expansion by default; if target is supplied, use S12 path
with its existing selectors and relation constraints. At most8 seeds, global shared
limits, no unbounded per-file/definition scans. Known occurrence/evidence IDs from S17
candidate provenance permit bounded primary-key proof hydration.

Retrieval interruption remains its bounded error, not false empty success. Navigation
may yield its existing truthful partial frontier; capture per-seed frontier/stop reason
and aggregate counters. Further seeds stop when shared allowance is exhausted. No
claims that an incomplete neighborhood/path is complete or that continuation renews
the search. Same-frontier replay includes all actual captured frontiers and effective
limits in the canonical domain.

### Whole attributed bundles and inspectable diversity

Every bundle is a self-contained, versioned atom with stable ID over its exact canonical
records/source references. Do not identify a bundle only by a display name or SQL rowid.
- Definition: exact entity plus genuine defining occurrence/evidence/producer when
  available, their complete ownership/provenance fields and exact source reference.
  Unknown/imported definition evidence is explicitly unavailable, not fabricated.
- Relationship: both endpoint identity projections plus complete assertion/evidence/
  occurrence/producer proof and supporting source reference; preserve relation,
  direction, resolution/confidence/unknown reasons and parallel assertion identities.
- Path: every ordered endpoint/hop proof in one indivisible atom. No successful path
  prefix or dropped supporting evidence to fit a byte/list limit.
- Lexical source: the native9 retrieval document identity, complete exact whole-file
  source reference and coverage/match provenance. It is a file-granularity match, not
  an invented assertion, definition occurrence or term-offset highlight.

Preserve all fields of canonical records admitted into a bundle. Descriptions of a
projection must say projection; no capped owner list may masquerade as a full entity.
Inline source, when selected by the fixed policy, is the ENTIRE referenced span, only
if available and within the finite raw-inline allowance. Read authenticated source via
the same held lease; use exact UTF-8 text when decodable, otherwise explicit base64.
Never replace invalid bytes or decode against live worktree content. If the span exceeds
the inline policy, the predeclared bundle variant is reference-only with an explicit
reason. This still includes all proof records; it does not claim source text was emitted.
No post-budget clipping or unnoticed switch of proof/uncertainty. Count inline yield and
reference availability separately during evaluation.

Rank with explicit versioned inspectable signals: original exact/lexical tier and seed
rank, hop distance, proof/source availability, and file/owner diversity. Use a bounded
deterministic policy: preserve the highest exact anchor first, then choose from sorted
per-file/owner queues in deterministic rounds, with seed rank/distance/stable bundle ID
as ties. Freeze the policy/version/weights or ordering tuple before evaluation. Avoid
unbounded degree scans; only observed candidate/expanded work can inform diagnostics.
Return the rank explanation, not an unsupported learned-relevance/confidence claim.

Deduplicate only truly identical bundle IDs; do not collapse parallel evidence or two
same-named definitions. Order the collected atoms once, apply deterministic inline
policy, then choose a prefix of WHOLE atoms that fits. Reserve metadata/diagnostics,
fingerprint, tokenizer fields and continuation/resource references first. Stop before
an atom exceeds byte/list allowance; do not silently reorder later tiny atoms to hide
omissions. Report selection/collection truncation and known/unknown totals distinctly.

### Exact emitted bytes and optional tokenizer self-reference

Admission measures actual SDK CallToolResult serialization, including structuredContent,
escaped compatibility text, flags, diagnostics, usage and next/resource references.
Use existing sdk_result/result_bytes; negotiated text-only and dual representations
must be accounted for honestly. JSON-RPC outer framing/request IDs remain separately
measured. No plain JSON length or raw source-byte count substitutes for full result size.

Optional Config tokenizer is an operator-supplied local object with bounded declared
algorithm ID/version and encode(str)->sequence. Requests cannot supply executable code,
load modules, URLs or change tokenizer authority. No particular model tokenizer is
mandated or installed. A reference UTF-8-byte tokenizer is exact only for that declared
algorithm, never a claim about model tokens. Test a second distinct deterministic local
encoding algorithm too. Operator code is trusted local configuration; do not claim
preemption of a blocking synchronous callback or hidden paid/network execution.

The exact token domain is UTF-8 decoding of the FINAL negotiated serialized MCP result
payload, including token_usage itself and compatibility text, excluding JSON-RPC framing.
Usage reports mode, algorithm ID/version, explicit domain and integer count. Set every
resource URI/cursor/usage field and representation before counting. Iterate count to a
fixed point, at most16 calls, detect cycles/nonconvergence/exception/invalid count, and
fail closed with a fixed bounded TOKENIZER_FAILED error. Never emit an inexact exact
count or relabel a failed exact tokenizer as an estimate. Re-serialize/recount the final
result and require equality; no later mutation may invalidate the count.

When no exact tokenizer is configured, mode=estimated and algorithm=byte_quarter.v1;
the explicit heuristic is ceil(final UTF-8 result bytes/4), not model tokens. Resolve
its self-reference deterministically too. Bound count to0..2^63-1, metadata string lengths
and callback invocations. Tokenizer failure errors do not claim exact usage. Preserve
this truth for both direct adapter tests and actual supported SDK protocol versions.

Reserve worst-case19 count digits and bounded URI/token lengths BEFORE selecting atoms,
so opaque token values or count digit changes cannot alter selected canonical evidence.
After final fixed-point accounting, enforce the byte cap again. Below the measured
minimum valid envelope return INVALID_BUDGET within the documented fixed server error
cap. Keep semantic output validation explicit; context errors/results cannot pass a
status/legacy union fallback. No 'exact' counts computed on dual output for a text-only
client, or computed before strings are escaped by the SDK.

### Continuation and typed resource membership

continuation=true captures a separately bounded ranked collection and all immutable
pages BEFORE issuing page1. Reuse S13 reservation/ownership/capacity/expiry/replay;
count all bundles/pages/descriptors/metadata/catalogs and packs under existing finite
limits. Never evict an unexpired promise. A too-large indivisible atom that cannot fit
any requested page is a bounded PAGE_TOO_SMALL error before issuance, not a dropped
path. No next cursor once the captured collection is exhausted; preserve original
search terminal reason across every page. Cached duplicate continuations do not rerun
retrieval/ranking/tokenization or mutate the frontier.

Add a context-page semantic schema and validate it before registry.install. Continuation
dispatch recognizes its saved projection while preserving old S13 page outputs. Bind
query digest to canonical context request, effective budgets/ranker/tokenizer declaration,
repo/G1 and actual protocol representation. Tokenizer declaration/config or authority
changes reject old context references; do not reinterpret cached usage under a new
algorithm. Keep old non-context lease behavior unchanged.

Retained resources use the existing generic token/owner/expiry/bounded chunk reader,
but issuance proof is a closed tagged union:
1. Existing assertion variant: exact assertion→evidence→occurrence→producer closure,
   unchanged, tied to a returned relationship/path proof.
2. Definition variant: exact returned entity→defining occurrence→evidence→producer,
   with matching source hashes/ranges and own-G1 source binding. No fake assertion.
3. Lexical file variant: exact returned native9 document ID/provenance, source path/hash,
   span[0,size), current indexed observation and authenticated source membership. No
   fake occurrence/evidence ID or authorization from an arbitrary min/max range alone.
Validate resource descriptors against the actual corresponding returned bundle, not
only their type/shape. Reject coherently rehashed foreign/mixed-generation records and
kind confusion. Legacy/sourcefree/failed stale unknowns never gain live-source fallback.

Default non-retained context emits immutable source references without a resource URI
or guarantee of later old-generation acquisition. Retained context keeps actual G1
SQLite+pack through G2/G3 pruning and normal/error/cancel/idle expiry/shutdown. Preserve
S13 actual same-kernel and host-macOS→Docker boundary, not advisory lock assumptions.
Resource responses retain exact base64/offset/URI/error caps; no source format changes.

### Stable canonical package and retrieval record

Define the canonical evidence package explicitly: normalized context request, repository/
generation/snapshot, ranker version/config, ordered complete selected bundles including
source/provenance/uncertainty, effective limits, coverage and deterministic frontier.
Each page has its stable selected bundle range and package fingerprint. A retrieval-record
ID is SHA256 of this canonical domain; selected evidence includes actual canonical facts,
not just opaque IDs. Exclude only enumerated operational presentation fields: random
lease/cursor/MAC/URI credentials, expiry/durations and emitted token-count diagnostics.
Keep stable resource identities and byte spans IN the domain; no evidence or uncertainty
may disappear merely because its presentation is leased. Tokenizer/ranker declaration
and inline policy remain included, while count differences between representations are
clearly diagnostic. Persisting retrieval records is an operator concern, not this server.

For the same request/snapshot/ranker and captured frontier, canonical evidence is equal
across independent issuances despite fresh lease credentials. Repeated SAME cursor
returns the exact saved page including credentials/count. Different selected evidence,
source hashes, relation/direction/filters or ranker configuration changes the identity.
Never hash clock fields or silently normalize source/proof fields to force replay.
